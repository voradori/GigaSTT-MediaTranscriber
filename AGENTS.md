# Инструкции для агентов

Этот репозиторий содержит небольшую Windows-утилиту на базе GigaSTT для локальной транскрибации аудио, видео и YouTube-источников с опциональным разделением говорящих.

Сначала прочитай `README.md`. Этот файл содержит правила работы с репозиторием. Документы из `docs/` читай по мере необходимости, когда задача затрагивает соответствующую подсистему.

## Цели проекта

Базовый сценарий должен оставаться простым и доступным без AI-агента:

1. установить основное окружение через `setup.cmd`;
2. положить локальные медиафайлы в `input/` либо использовать `youtube.cmd`;
3. запустить транскрибацию;
4. получить результаты в `output/transcripts/`.

Основная транскрибация через GigaSTT должна оставаться работоспособной без Codex, других LLM, Docker, CUDA и подключения к интернету после первоначальной установки моделей.

Обработка с помощью AI является дополнительным уровнем поверх основной системы. Агент может запускать имеющиеся команды, читать полученные TXT/JSON-файлы и использовать их для создания заметок по встречам, кратких выжимок, списков задач, решений и других производных материалов.

Не делай LLM обязательной runtime-зависимостью транскрибации.

## Структура репозитория

### Пользовательские точки входа

- `setup.cmd` — установка базового окружения, локальных медиа-инструментов и GigaSTT;
- `transcribe.cmd` — транскрибация локальных файлов из `input/`;
- `youtube.cmd` — загрузка и транскрибация YouTube-видео или плейлиста;
- `setup-diarization.cmd` — установка дополнительного стека для разделения говорящих;
- `transcribe_dr.cmd` — транскрибация локальных файлов с последующим разделением говорящих;
- `youtube_dr.cmd` — загрузка YouTube, транскрибация и разделение говорящих;
- `diarize.cmd` — добавление разделения говорящих к уже существующим транскриптам без повторного распознавания речи;
- `download-audio.cmd` — загрузка исходного аудио без запуска транскрибации.

Сохраняй эти точки входа пригодными для обычного пользователя. Для стандартного использования не должно требоваться вручную запускать Python-скрипты.

### Реализация

- `scripts/` — Python- и PowerShell-реализация, используемая `.cmd`-файлами;
- `requirements-youtube.txt` — Python-зависимости для работы с YouTube;
- `requirements-diarization.txt` — дополнительные зависимости для разделения говорящих.

Предпочитай расширять существующие скрипты, а не создавать дополнительные уровни обёрток без практической необходимости.

### Документация

- `README.md` — публичное описание, установка и обычное использование. Должен оставаться понятным не-разработчику;
- `THIRD_PARTY.md` — основные сторонние программы, библиотеки, модели и информация об их лицензиях;
- `docs/SPEAKER_IDENTIFICATION.md` — разделение говорящих, повторная обработка и правила сопоставления меток голосов с реальными людьми;
- `docs/SYSTEM.md` — текущее устройство системы, проверенное поведение и важные технические решения.

Если изменение кода делает какой-либо из этих документов существенно неверным, обнови соответствующий документ в рамках того же изменения.

## Локальные и генерируемые данные

Следующие данные являются локальными и не должны попадать в Git:

- `input/`;
- `output/`;
- `tools/`;
- `models/`;
- `.venv/`;
- временные файлы;
- скачанные медиафайлы;
- кеши моделей;
- журналы выполнения.

Не предполагай наличие каких-либо абсолютных путей за пределами репозитория. Все пути проекта определяй относительно корня репозитория.

Не изменяй, не переименовывай и не удаляй исходные аудио- и видеофайлы в рамках обычной обработки.

Избегай ненужного копирования больших медиафайлов.

## Контракт результатов

Для каждого успешно обработанного источника сохраняй исходный результат распознавателя и нормализованную версию.

Основные файлы результатов:

- `raw.json` — исходный результат распознавания;
- `transcript.json` — нормализованный структурированный транскрипт;
- `transcript.txt` — читаемый человеком транскрипт;
- `diarization.json` — результат разделения говорящих, если оно использовалось;
- `error.txt` — информация об ошибке, если обработка завершилась неуспешно.

Не перезаписывай молча корректные завершённые результаты.

Если существующий результат повреждён или внутренне противоречив, сообщи об этом или останови обработку вместо того, чтобы считать его корректным.

Смысловая выжимка, заметки встречи или итоговый документ являются производными материалами. Не выдавай их за дословный транскрипт.

## Работа с говорящими

Метки вида `SPEAKER_00` обозначают различимые голоса внутри конкретной записи. Они не устанавливают личность человека.

Не присваивай голосу реальное имя без достаточных оснований.

Не приписывай конкретному человеку слова, решения или задачи только потому, что метки голосов кажутся похожими в разных записях.

Если задача затрагивает разделение голосов, повторный запуск модели или определение реальных говорящих, сначала прочитай `docs/SPEAKER_IDENTIFICATION.md`.

## Внешние инструменты и секреты

Не читай, не печатай и не коммить значения токенов, паролей, `.env` или других секретов.

Если внешний инструмент требует авторизации, используй его штатный механизм авторизации вместо ручного извлечения учётных данных.

Сторонние программы, библиотеки и модели сохраняют собственные лицензии и условия использования. См. `THIRD_PARTY.md`.

## Стиль работы

Это небольшая практическая утилита, а не enterprise-платформа.

Предпочитай минимальное изменение, которое решает реальную пользовательскую задачу.

Не добавляй дополнительные сервисные слои, архитектурные абстракции, сложные системы конфигурации или большую тестовую инфраструктуру без конкретной практической причины.

Сохраняй простые `.cmd`-точки входа даже в случае изменения внутренней реализации.

Держи изменения узкими. Не переписывай работающий код, не относящийся к текущей задаче.

Каждый законченный и проверенный логический этап коммить отдельно. Не коммить локальные медиафайлы, результаты транскрибации, модели или незавершённые эксперименты.

## Проверка изменений

Проверяй тот сценарий, который реально затронут изменением, вместо механического прогона всех возможных вариантов.

В качестве репрезентативных входов можно использовать:

- короткий аудиофайл для smoke-теста;
- более крупный MP3 для обычной пакетной обработки;
- MP4 при изменениях обработки видео;
- YouTube-видео или плейлист при изменениях загрузки;
- запись с несколькими голосами при изменениях разделения говорящих.

Успешный короткий smoke-тест подтверждает только работу короткого smoke-теста.

Не утверждай, что проверены длинные записи, плейлисты или разделение нескольких говорящих, если такие сценарии фактически не запускались.

В отчёте указывай, что именно было проверено, какие результаты получены и какие ограничения остались.

Не превращай техническую документацию в хронологический дневник разработки или журнал локальных экспериментов.
