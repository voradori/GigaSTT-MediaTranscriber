# Локальная транскрибация

Проект для автономной расшифровки русскоязычных созвонов, видео и голосовых сообщений. Целевой сценарий: положить файлы в `input/`, запустить один локальный `.cmd` и получить результаты в `output/`. После первоначальной установки моделей распознавание должно работать без интернета, Codex и других LLM.

## Состояние

Первый рабочий срез использует Windows CLI [GigaSTT](https://github.com/ekhodzitsky/gigastt) 2.21.0 на CPU. Отдельный необязательный проход через локальную Community-1 добавляет условные метки голосов к уже готовому транскрипту, не повторяя распознавание речи. `summary.md` создаётся агентом отдельно, по запросу; автономный запуск от него не зависит.

## Запуск

Выбери режим заранее: `transcribe.cmd` и `youtube.cmd` создают только текст, а `transcribe_dr.cmd` и `youtube_dr.cmd` добавляют к тому же итоговому транскрипту метки голосов. Команды `_dr` требуют отдельной установки Community-1. Без параметров локальные команды обрабатывают весь `input/`; переданное имя файла или папки ограничивает проход.

Один раз при наличии интернета запусти `setup.cmd`: он скачивает Windows-бинарник, распознаватель и модель пунктуации в локальные игнорируемые Git папки `tools/` и `models/`, проверяет SHA-256 архива. Нужны Python и, для MP4, ffmpeg в PATH. Затем положи записи в `input/` и запусти `transcribe.cmd`. Например, `transcribe.cmd "папка"` или `transcribe_dr.cmd "папка\запись.mp3"` ограничивает проход выбранным входом. Распознавание запускается с `--offline`, без Docker, Codex и сети. Поддерживаются OGG, OPUS, MP3, WAV, M4A, FLAC, WebM и MP4 с аудиодорожкой AAC; для MP4 дорожка временно извлекается без перекодирования.

Для каждого файла создаётся `output/transcripts/<путь файла в input/>/`. Если там уже есть все три читаемых результата, повторный запуск пропускает его; повреждённый готовый JSON блокирует перезапись и требует проверки. После ошибки распознавания остаётся `error.txt`, а неполную обработку можно повторить. Для очень больших записей пока нет проверки восстановления с середины: повтор начинается заново.

Для YouTube запусти `youtube.cmd` (только текст) или `youtube_dr.cmd` (текст и голоса) и вставь ссылку на ролик или плейлист. Нужны интернет для скачивания и установленный `yt-dlp` (системный или установленный вместе с диаризацией); само распознавание остаётся локальным. Для JavaScript-проверок YouTube нужен Node.js 22+ и пакет EJS: без `.venv` установи один раз `python -m pip install --user "yt-dlp[default]==2026.8.19"`, а `setup-diarization.cmd` ставит этот пакет в `.venv` сам. Скрипт включает Node автоматически, если он доступен в PATH. Команда обрабатывает только аудиофайлы, полученные или пропущенные как уже скачанные для переданной ссылки, а не весь `input/`. Ролики плейлиста складываются в `input/<название плейлиста>/`, а их результаты — в `output/transcripts/<название плейлиста>/`. У одиночной ссылки папка называется `YouTube videos`. В имени ролика есть название и ID; повторный запуск пропускает уже скачанное аудио и готовые результаты.

## Необязательное разделение голосов

Один раз прими условия доступа к [Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) и запусти `setup-diarization.cmd`. Установщик создаёт локальную `.venv`, ставит FFmpeg Shared через `winget`, запрашивает токен Hugging Face при необходимости и загружает модель в игнорируемую папку `models/`.

Если транскрипт уже существует, но исходного аудио нет, используй `download-audio.cmd`: он скачивает только звук и никогда не вызывает GigaSTT. Для уже готового текста запусти `diarize.cmd` (или укажи папку, файл либо `--id VIDEO_ID`). Для новых записей используй команды `_dr`, если нужны голоса. Создаётся `diarization.json`, а метки записываются в основные `transcript.json` и `transcript.txt`; `raw.json` не меняется. Повторный запуск пропускает готовые результаты, а ошибка одного файла не останавливает обработку остальных. `SPEAKER_00` означает различимый голос только внутри конкретной записи, а не установленную личность.

## Результат для каждого исходного файла

- `raw.json` — неизменённый экспорт распознавателя;
- `transcript.json` — итоговая структура с текстом и таймкодами, при запуске `_dr` также с метками голосов;
- `transcript.txt` — итоговый читаемый текст, при запуске `_dr` с метками голосов;
- `diarization.json` — необязательные временные отрезки голосов Community-1;
- `summary.md` — необязательная смысловая выжимка, создаваемая агентом отдельно от автономного распознавания.

Исходные файлы не изменяются. Сырые результаты сохраняются даже при последующей редактуре текста или тезисов. Для агентского сопоставления голосов с именами см. [SPEAKER_IDENTIFICATION.md](docs/SPEAKER_IDENTIFICATION.md). Для новых файлов работает локальная пунктуация GigaSTT; она не всегда расставляет знаки удачно. Ранее готовые папки не перезаписываются новым форматом автоматически.

## Папки

- `input/` — локальные входные файлы и скачанные аудиодорожки, не входят в Git;
- `output/transcripts/` — пользовательские результаты, повторяет вложенные папки `input/`, не входит в Git;
- `output/technical/` — технические пробы, отдельно от пользовательских результатов, не входит в Git;
- `docs/ROADMAP.md` — этапы реализации и проверки;
- `docs/SYSTEM.md` — рабочий стек, результаты проверок и причины решений;
- `G:\Vault\DockerCache\` — отдельное место для Docker-данных и кешей, вне этого репозитория. Существующее содержимое не удалять и не переносить без конкретной необходимости.

Рабочие примеры находятся в `G:\Household\sozvon\`; это внешние исходники и часть проекта в Git не входят.

## Для агента

Начинай с этого README, затем читай `AGENTS.md` и нужный раздел `docs/`. Для повторения разделения голосов на другом компьютере следуй [DIARIZATION.md](docs/DIARIZATION.md). Не считай план реализованной функциональностью. Перед обработкой файлов проверь доступность локальных инструментов и сохрани исходные записи неизменными.
