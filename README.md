# GigaSTT Media Transcriber

Локальный инструмент для расшифровки русскоязычных аудио и видео на Windows. Использует [GigaSTT](https://github.com/ekhodzitsky/gigastt) для распознавания речи, умеет обрабатывать локальные файлы и YouTube-видео/плейлисты, а также опционально добавлять разделение говорящих через [pyannote Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1).

Обычная транскрибация через GigaSTT работает на CPU: NVIDIA GPU и CUDA не требуются. После первоначальной установки моделей локальные файлы можно расшифровывать полностью офлайн, без облачных API, Docker и внешних LLM. Результаты сохраняются в читаемом TXT и структурированном JSON с таймкодами.

## Что это за проект

Это небольшой инструмент, изначально собранный для собственного использования и в значительной степени навайбкоженный через Codex с GPT-5.6 Sol Light. Код не претендует на архитектурное совершенство, промышленное качество или звание нового стандарта обработки речи. Он решает конкретную задачу, которой мне не хотелось заниматься вручную, и распространяется **as is**. Если что-то работает странно, криво или недостаточно элегантно — вполне возможно, так оно и есть.

Основная цель проекта — не просто получить текст из аудио, а подготовить записи для дальнейшей обработки человеком, LLM или локальным/облачным агентом. Типичный сценарий: пачкой положить записи созвонов, голосовые сообщения из мессенджеров, видео или YouTube-плейлист, получить структурированные транскрипты с таймкодами и, при необходимости, разделением говорящих, а затем передать результат агенту для составления meeting notes, краткой выжимки, списка решений, задач, важных фактов или других итоговых материалов.

При этом проект специально не требует LLM или AI-агента для обычного использования. Для установки и обработки предусмотрены отдельные `.cmd`-файлы, поэтому весь основной workflow можно выполнять вручную: установить зависимости, положить файлы в `input/`, запустить нужную команду и забрать готовые результаты из `output/`.

Для обычной транскрибации используются `transcribe.cmd` и `youtube.cmd`. Они создают текст и структурированный транскрипт без разделения говорящих.

Версии с суффиксом `_dr` — `transcribe_dr.cmd` и `youtube_dr.cmd` — выполняют ту же обработку, но дополнительно запускают разделение говорящих. Для уже готового транскрипта можно отдельно использовать `diarize.cmd`, не повторяя распознавание речи.

Если же у пользователя есть AI-агент с доступом к командной строке и рабочей папке, проект хорошо подходит для автоматизированного сценария: агент может сам запустить распознавание, прочитать полученные JSON/TXT и сразу продолжить обработку результатов. Именно такой agent-assisted workflow был одной из исходных причин появления проекта, но он остаётся необязательным.

## Возможности

- локальная русскоязычная транскрибация через GigaSTT;
- работа основной транскрибации на CPU без CUDA;
- пакетная обработка файлов и папок;
- загрузка аудио из YouTube через yt-dlp;
- поддержка YouTube-плейлистов;
- опциональное разделение говорящих через pyannote Community-1;
- сохранение исходного результата распознавателя и нормализованного транскрипта;
- повторный запуск без повторной обработки уже готовых файлов;
- работа без сети после первоначальной установки моделей;
- простой Windows-интерфейс через `.cmd`-файлы без необходимости вручную запускать Python-скрипты.

## Требования

### Для обычной транскрибации

- Windows x64;
- Python 3;
- обычный CPU;
- NVIDIA GPU и CUDA не требуются;
- интернет нужен только для первоначальной установки инструментов и моделей.

Дополнительно:

- FFmpeg нужен для MP4 и MKV: локальная копия в `tools/ffmpeg/` используется первой, иначе нужен FFmpeg в `PATH`;
- Node.js 22+ рекомендуется для современных JavaScript-проверок YouTube.

### Для разделения говорящих

Разделение говорящих устанавливается отдельно и использует значительно более тяжёлый ML-стек. Текущий установщик ставит CUDA-сборку PyTorch и в первую очередь рассчитан на NVIDIA GPU.

- NVIDIA GPU с CUDA рекомендуется для нормальной скорости обработки;
- если CUDA недоступна, скрипт переключается на CPU;
- дополнительная установка выполняется через `setup-diarization.cmd`.

Если разделение говорящих не нужно, этот дополнительный стек устанавливать не требуется.

## Быстрый старт

1. Клонируйте репозиторий.
2. При наличии интернета запустите `setup.cmd`.
3. Поместите аудио или видео в папку `input/`.
4. Запустите `transcribe.cmd`.
5. Готовые результаты появятся в `output/transcripts/`.

Без параметров `transcribe.cmd` обрабатывает все поддерживаемые файлы внутри `input/`. Можно обработать только конкретный файл или папку:

```text
transcribe.cmd "recording.mp3"
transcribe.cmd "meetings"
```

Поддерживаются OGG, OPUS, MP3, WAV, M4A, FLAC, WebM, MP4 и MKV. Для MP4 аудиодорожка временно копируется через FFmpeg, для MKV временно декодируется в WAV. Исходный видеофайл не изменяется.

`setup.cmd` создаёт локальную `.venv`, устанавливает инструменты для YouTube, скачивает актуальный Windows-релиз GigaSTT и необходимые модели в локальные папки `tools/` и `models/`. Эти папки не входят в Git.

## YouTube

Запустите:

```text
youtube.cmd
```

и вставьте ссылку на отдельное видео или плейлист.

Скрипт скачивает аудиодорожку через [yt-dlp](https://github.com/yt-dlp/yt-dlp), сохраняет её в `input/` и передаёт локальному распознавателю. Для загрузки YouTube нужен интернет; само распознавание после скачивания выполняется локально.

Повторный запуск не перезаписывает уже скачанное аудио и пропускает готовые результаты.

## Разделение говорящих

Разделение говорящих является необязательным компонентом и устанавливается отдельно. Основная транскрибация через GigaSTT от него не зависит и продолжает работать на CPU без CUDA.

После основного `setup.cmd` запустите:

```text
setup-diarization.cmd
```

Установщик добавит зависимости [pyannote.audio](https://github.com/pyannote/pyannote-audio), при необходимости настроит FFmpeg Shared и загрузит модель Community-1. Для загрузки модели необходимо принять условия доступа на Hugging Face и авторизоваться.

После установки доступны:

```text
transcribe_dr.cmd
youtube_dr.cmd
diarize.cmd
```

- `transcribe_dr.cmd` — транскрибация локальных файлов + разделение голосов;
- `youtube_dr.cmd` — загрузка YouTube + транскрибация + разделение голосов;
- `diarize.cmd` — добавление голосов к уже существующему транскрипту без повторного распознавания речи.

Если транскрипт уже существует, но исходное YouTube-аудио было удалено, `download-audio.cmd` скачивает только звук и не запускает GigaSTT.

Метки вида `SPEAKER_00`, `SPEAKER_01` обозначают разные голоса только внутри конкретной записи и сами по себе не определяют личность говорящего.

Подробнее: [разделение и идентификация говорящих](docs/SPEAKER_IDENTIFICATION.md).

## Результаты

Для каждого исходного файла создаётся отдельная папка в `output/transcripts/`, повторяющая структуру `input/`.

Основные файлы:

- `raw.json` — исходный экспорт GigaSTT;
- `transcript.json` — нормализованный транскрипт с текстом и таймкодами;
- `transcript.txt` — читаемая текстовая версия;
- `diarization.json` — интервалы говорящих, если использовалось разделение голосов;
- `error.txt` — информация об ошибке, если обработка не завершилась.

Исходные медиафайлы не изменяются. Если все основные результаты уже существуют и читаются корректно, повторный запуск пропускает файл. Повреждённые существующие результаты не перезаписываются автоматически.

## Сеть и приватность

После первоначальной загрузки GigaSTT и его моделей транскрибация локальных файлов выполняется офлайн.

Сеть требуется для:

- первоначальной установки инструментов и моделей;
- загрузки YouTube;
- первоначальной загрузки pyannote Community-1.

Аудио не отправляется в облачный сервис распознавания.

## Ограничения

- проект в первую очередь ориентирован на Windows;
- распознавание ориентировано на русскую речь;
- качество пунктуации зависит от моделей GigaSTT и иногда требует ручной правки;
- после прерывания обработки большого файла распознавание начинается заново: восстановления с промежуточной позиции пока нет;
- разделение говорящих заметно тяжелее обычной транскрибации; для него рекомендуется NVIDIA GPU с CUDA, хотя при недоступной CUDA скрипт может работать на CPU.

## Структура репозитория

- `input/` — локальные исходные файлы и скачанные аудиодорожки; не входит в Git;
- `output/transcripts/` — пользовательские результаты; не входит в Git;
- `output/technical/` — технические результаты и проверки; не входит в Git;
- `scripts/` — Python и PowerShell-скрипты;
- `docs/SPEAKER_IDENTIFICATION.md` — разделение говорящих и сопоставление условных меток голосов с именами;
- `docs/SYSTEM.md` — технические детали и принятые решения.
