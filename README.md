# Локальная транскрибация

Проект для автономной расшифровки русскоязычных созвонов, видео и голосовых сообщений. Целевой сценарий: положить файлы в `input/`, запустить один локальный `.cmd` и получить результаты в `output/`. После первоначальной установки моделей распознавание должно работать без интернета, Codex и других LLM.

## Состояние

Первый рабочий срез использует Windows CLI [GigaSTT](https://github.com/ekhodzitsky/gigastt) 2.21.0 на CPU. Диаризация в этом режиме пока не подключена. `summary.md` создаётся агентом отдельно, по запросу; автономный запуск от него не зависит.

## Запуск

Один раз при наличии интернета запусти `setup.cmd`: он скачивает Windows-бинарник, распознаватель и модель пунктуации в локальные игнорируемые Git папки `tools/` и `models/`, проверяет SHA-256 архива. Нужны Python и, для MP4, ffmpeg в PATH. Затем положи записи в `input/` и запусти `transcribe.cmd`. Распознавание запускается с `--offline`, без Docker, Codex и сети. Поддерживаются OGG, OPUS, MP3, WAV, M4A, FLAC, WebM и MP4 с аудиодорожкой AAC; для MP4 дорожка временно извлекается без перекодирования.

Для каждого файла создаётся `output/<имя файла>/`. Если там уже есть все три успешных результата, повторный запуск пропускает его. Прерванную обработку можно повторить. Для очень больших записей пока нет проверки восстановления с середины: повтор начинается заново.

## Результат для каждого исходного файла

- `raw.json` — неизменённый экспорт распознавателя;
- `transcript.json` — единая структура с текстом, таймкодами и доступными метками спикеров;
- `transcript.txt` — читаемые строки вида `(0:01) Текст...`, при наличии спикеров с их метками;
- `summary.md` — необязательная смысловая выжимка, создаваемая агентом отдельно от автономного распознавания.

Исходные файлы не изменяются. Сырые результаты сохраняются даже при последующей редактуре текста или тезисов. Для новых файлов работает локальная пунктуация GigaSTT; она не всегда расставляет знаки удачно. Ранее готовые папки не перезаписываются новым форматом автоматически.

## Папки

- `input/` — локальные входные файлы, не входят в Git;
- `output/` — локальные результаты, не входят в Git;
- `docs/ROADMAP.md` — этапы реализации и проверки;
- `docs/SYSTEM.md` — рабочий стек, результаты проверок и причины решений;
- `G:\Vault\DockerCache\` — отдельное место для Docker-данных и кешей, вне этого репозитория. Существующее содержимое не удалять и не переносить без конкретной необходимости.

Рабочие примеры находятся в `G:\Household\sozvon\`; это внешние исходники и часть проекта в Git не входят.

## Для агента

Начинай с этого README, затем читай `AGENTS.md` и нужный раздел `docs/`. Не считай план реализованной функциональностью. Перед обработкой файлов проверь доступность локальных инструментов и сохрани исходные записи неизменными.
