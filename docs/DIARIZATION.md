# Как повторить разделение записей по говорящим

Эта инструкция предназначена для следующего Кодекса или человека, который продолжает работу на другом Windows-компьютере. Исследовать выбор модели заново не нужно: рабочий вариант уже проверен на реальных файлах.

## Что уже решено

Для разделения голосов используется локальная модель [pyannote Speaker Diarization Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1). Она запускается отдельно от GigaSTT и не распознаёт речь повторно. Готовый текст и таймкоды слов берутся из существующих `transcript.json`, а модель определяет только временные отрезки голосов.

`raw.json` не меняется. `diarization.json` хранит отрезки голосов Community-1; метки слов и отрезков записываются в итоговый `transcript.json`, а `transcript.txt` получает строки вида `(0:12) [SPEAKER_00] ...`. Дополнительная пара `transcript.speakers.*` для новых результатов не создаётся.

`SPEAKER_00` — условное имя голоса только внутри одной записи. Оно не означает установленную личность и не обязано обозначать одного и того же человека в разных роликах.

## Что должно быть на компьютере

- Windows и Python, доступный командой `python`;
- видеокарта NVIDIA с CUDA желательна, но при её отсутствии скрипт перейдёт на CPU;
- доступ в интернет во время установки модели и скачивания звука;
- аккаунт Hugging Face с принятыми условиями Community-1;
- существующие папки с `output/**/transcript.json`.

Модель, виртуальное окружение, аудио и результаты исключены из Git. Данные доступа Hugging Face нельзя записывать в файлы проекта или коммиты.

## Установка

1. На странице Community-1 войти в Hugging Face и принять условия доступа к модели.
2. Войти в аккаунт Hugging Face в браузере. Если CLI попросит авторизацию, он покажет ссылку и одноразовый код устройства.
3. Сначала выполнить `setup.cmd`, который создаёт общую `.venv` и устанавливает GigaSTT с YouTube-инструментами. Затем из корня проекта запустить:

   ```powershell
   .\setup-diarization.cmd
   ```

4. Если появится запрос авторизации, открыть указанную ссылку в браузере и ввести одноразовый код устройства; токен в чат не отправлять. Установщик дополнит ту же `.venv` CUDA-версиями PyTorch и pyannote, при необходимости поставит FFmpeg Shared, затем скачает модель в `models/pyannote-speaker-diarization-community-1`.
5. Успешная проверка в конце должна показать версию pyannote и `CUDA: True` на компьютере с подходящей NVIDIA-видеокартой.

Установщик и рабочий скрипт сами находят FFmpeg, установленный WinGet, даже если новый путь ещё не появился в текущем PowerShell. Предупреждение Windows о файле `PSReadLine.format.ps1xml` относится к подписанному модулю Microsoft; при однократном запуске можно выбрать `R`.

## Получение звука без повторного STT

Если в `output` уже есть расшифровки, но исходных видео или аудио нет, запустить:

```powershell
.\download-audio.cmd
```

Вставить ссылку на ролик или плейлист в появившийся запрос. Команда скачивает только лучшую доступную аудиодорожку и не вызывает GigaSTT. ID YouTube сохраняется в имени файла в квадратных скобках; по нему звук однозначно сопоставляется с папкой транскрипта.

Проверенные плейлисты:

- `https://www.youtube.com/playlist?list=PLVfLJFEB_hPW-LROptgJsuMFxOUv1kRXW` — пять частей в папке «Прямые трансляции»;
- `https://www.youtube.com/playlist?list=PLVfLJFEB_hPXdvX5MP8B1Asd84HWQXfHz` — 224 ролика в папке «Сергей Тармашев： Ответы на вопросы читателей».

Перед запуском модели скрипт сам проверяет, что длительность найденного аудио отличается от длительности транскрипта не более чем на одну секунду. Если совпадения по ID нет, найден дубль или длительность расходится, этот файл получает сообщение `FAILED`, но остальные продолжают обрабатываться.

## Запуск и продолжение после остановки

Для всех найденных транскриптов:

```powershell
.\diarize.cmd
```

Для одного ролика:

```powershell
.\diarize.cmd --id VIDEO_ID
```

Повторный запуск безопасен: готовые комплекты пропускаются. Старые `transcript.speakers.*` удаляются при переносе в основной транскрипт только при точном совпадении содержимого; отличающиеся файлы сохраняются для проверки. После остановки достаточно снова выполнить `diarize.cmd`; уже законченные записи не пересчитываются. Временный WAV 16 кГц создаётся только на время обработки одного WebM и удаляется после успеха или ошибки.

`--force` заново строит файлы транскрипта с говорящими, используя сохранённый `diarization.json`, то есть без повторного запуска модели. `--rerun-model` заново выполняет Community-1 и заменяет файлы с разметкой. Если агент уже добавил `speaker_names`, повтор модели блокируется до ручной проверки: индексы голосов могут измениться. `raw.json` не меняется; итоговые `transcript.json` и `transcript.txt` обновляются.

Для новых записей после установки модели используй `transcribe_dr.cmd` или `youtube_dr.cmd`. Команды без `_dr` делают только текст. `youtube_dr.cmd` ограничивает оба этапа файлами переданной ссылки. Для работы с уже готовыми результатами оставлен `diarize.cmd`; ему можно передать имя файла или папки внутри `input/`, либо `--id VIDEO_ID`.

## Как проверить результат

Повторный запуск `diarize.cmd` для выбранного файла должен вывести `SKIP existing` и завершиться кодом 0. В его папке результата должны быть `raw.json`, `transcript.json`, `transcript.txt` и `diarization.json`, а временного `diarization-input.wav` после завершения быть не должно. Общие количества по всему `output/` сравнивать нельзя: часть записей может быть обработана только в текстовом режиме. Старые копии `transcript.speakers.*` могут остаться, если их содержимое отличается от нового результата, и требуют отдельной проверки.

## Проверенный результат на этом компьютере

На RTX 3060 Laptop 6 ГБ успешно обработаны 229 записей: пять из первого плейлиста и 224 из второго. Для второго плейлиста набор ID полностью совпал с набором существующих транскриптов, а длительности аудио отличались не более чем на 0,001 секунды. Метки получили 215273 из 215475 слов — 99,906%; 202 слова оставлены `UNKNOWN`.

Техническая полнота файлов проверена, но правильность каждой смены говорящего ещё не подтверждена прослушиванием. В первую очередь следует проверить выпуски №1, 2, 10, 17, 18, 31 и ролик «Судьба инструктора из аномальной зоны Ареал + бонус»: в них Community-1 нашла больше трёх голосовых меток и могла разделить один реальный голос на несколько.
