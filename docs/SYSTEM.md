# Как работает текущий срез

Этот документ описывает проверенную реализацию и причины выбора. Текущие задачи — в [ROADMAP.md](ROADMAP.md); план там не означает работающую функцию.

## Путь файла

1. `setup.cmd` один раз получает актуальный Windows-релиз GigaSTT с GitHub, проверяет SHA-256 архива и скачивает модели распознавания и пунктуации в `tools/` и `models/`. Обе папки исключены из Git. Проверенный на этой машине релиз — GigaSTT 2.21.0. Загрузка пунктуации проверена отдельным запуском на коротком синтетическом WAV.
2. Пользователь кладёт запись в `input/` и запускает `transcribe.cmd`. Python-скрипт выбирает поддерживаемые файлы. Для MP4 `ffmpeg` копирует первую аудиодорожку в временный `extracting.m4a`, не меняя исходное видео; после успешной обработки временный файл удаляется.
3. Windows CLI GigaSTT распознаёт файл на CPU с `--offline`, применяет локальную модель пунктуации и пишет исходный JSON в `output/<имя файла>/raw.json`. ITN пока отключена. Процесс GigaSTT завершается после каждого файла; постоянного сервера нет.
4. Скрипт сопоставляет оформленный текст со словами и таймкодами raw-экспорта и создаёт `transcript.json` и строки `(м:сс) Текст...` в `transcript.txt`. Он делит строки на паузах, после конечных знаков и по ограничению длины. Если текст модели не удаётся однозначно сопоставить со словами, используются исходные слова без оформления. Если все три результата уже есть, файл пропускается без перезаписи.

Транскрипция не требует Codex, LLM или Docker. `summary.md` — отдельная будущая работа агента по запросу, а не часть этого запуска. Работа при физически отключённой сети ещё не проверялась; `--offline` запрещает сетевую загрузку во время распознавания.

## Проверено на этой машине

- RTX 4080, Docker Desktop и `ffmpeg` доступны, но выбранный Windows CLI работает на CPU; GPU и Docker в текущем пути не используются.
- Пять Telegram OGG длительностью 14–54 с и MP3 созвона длительностью 53:16 прошли через `transcribe.cmd`. Для MP3 распознавание заняло около 106 с. У каждого есть `raw.json`, `transcript.json`, `transcript.txt`.
- MP4 того же созвона (исходный файл 11,3 ГБ) прошёл целиком: аудиодорожка 53:19, общий проход с извлечением занял около 105 с. Временный аудиофайл после успеха отсутствует.
- Повторный запуск пропустил все готовые папки. Входные файлы для проверки были связаны жёсткими ссылками, без копирования большого видео и без изменения оригиналов.
- Сравнение пяти OGG с внешней расшифровкой показало сохранение основных мыслей и чисел, но худшую пунктуацию и деление на фразы; есть отдельные ошибки слов. Меток спикеров в результатах пока нет.
- Локальная пунктуация проверена отдельно на OGG и полном MP3 (53:16, около 100 с). На MP3 все 7051 распознанное слово и его таймкод совпали с первым прогоном; в оформленном тексте появились знаки. Разбиение выросло с 383 до 720 строк; некоторые знаки и границы всё ещё выглядят ошибочными. Старые результаты оставлены для сравнения.
- Сопоставление исходных MP3 и MP4 результатов дало 6927 совпавших слов в последовательности из примерно 7,1 тыс. (отношение совпадения 0,979), но MP4-аудио длиннее на 2,82 с, а медианный сдвиг совпавших таймкодов — 1,48 с. Это сравнение двух экспортов, не оценка точности относительно записи.

## Выбор технологий и границы

- **Принято: Windows CLI GigaSTT + локальные модели.** На реальных OGG, MP3 и MP4 он дал результат без постоянно работающего сервиса. CPU-скорости оказалось достаточно для первого удобного среза. `raw.json` хранит прямой экспорт движка, а производные файлы можно менять позже.
- **Принято: Python для пакетного запуска и форматов результата; `ffmpeg` только для видео.** Это обеспечивает один пользовательский `.cmd`, отдельную папку на файл и сохранение исходной записи.
- **Docker/CUDA пока не включены в рабочий путь.** Они были в первоначальном архитектурном примере, но пользователь не настаивает на Docker, а CPU-проверка закрыла первый сценарий. Это не вывод о качестве или скорости GPU-варианта: его не тестировали.
- **Встроенная диаризация GigaSTT отложена до пробы на созвоне.** Модель спикеров скачана при установке, но текущая CLI-команда её не включает. Отдельный pyannote не добавляли: сначала нужно оценить встроенное разделение голосов на реальной записи.
- **Принято: встроенная локальная пунктуация GigaSTT для новых заданий.** Она даёт знаки без LLM, сети при запуске и отдельного сервиса. Качество разбиения остаётся открытым: вывод внешнего STT местами читается лучше, а старые `raw.json` и транскрипты нельзя переписывать ради оформления.

Пока не проверены работа без физической сети, сбои и восстановление на большом файле, созвоны 1–3 часа и качество диаризации. Наличие трёх файлов считается успешным результатом текущего запуска; повреждённый, но формально существующий результат пока автоматически не выявляется.
