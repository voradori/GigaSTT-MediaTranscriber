# Устройство системы

Этот документ описывает текущую реализацию GigaSTT Media Transcriber и важные технические решения. Пользовательская установка и обычные команды находятся в `README.md`.

## Общий поток данных

1. `setup.cmd` создаёт общую `.venv`, устанавливает зависимости для YouTube и загружает локальные FFmpeg Shared и Node.js LTS, Windows-релиз GigaSTT и необходимые модели в `tools/` и `models/`.
2. Локальные файлы помещаются в `input/`. Для YouTube `youtube.cmd` или `youtube_dr.cmd` скачивают аудиодорожки через `yt-dlp` и также сохраняют их внутри `input/`.
3. `scripts/transcribe.py` запускает локальный `gigastt.exe` в offline-режиме, применяет локальную модель пунктуации и сохраняет исходный экспорт в `raw.json`.
4. Исходный результат нормализуется в `transcript.json` и читаемый `transcript.txt` с таймкодами.
5. При использовании `_dr`-команд или отдельного `diarize.cmd` Community-1 определяет интервалы разных голосов и добавляет метки в основной транскрипт. `raw.json` при этом не меняется.
6. Готовые TXT/JSON-файлы могут использоваться человеком, обычным чатом или AI-агентом для дальнейшей смысловой обработки. Этот этап не входит в базовую транскрибацию.

## Базовая транскрибация

Основной движок — Windows CLI [GigaSTT](https://github.com/ekhodzitsky/gigastt).

Рабочий путь использует CPU и не требует NVIDIA GPU, CUDA, Docker или постоянно работающего сервиса. GigaSTT запускается отдельно для каждого файла с локальными моделями и параметром `--offline`. Пунктуация применяется локально. ITN в текущей реализации отключена.

Поддерживаемые аудиоформаты:

- OGG;
- OPUS;
- MP3;
- WAV;
- M4A;
- FLAC;
- WebM.

Также поддерживаются MP4 и MKV. Для MP4 FFmpeg временно копирует первую аудиодорожку в M4A без перекодирования; для MKV декодирует её во временный WAV 16 кГц моно. Исходный видеофайл не изменяется, временный файл удаляется после завершения обработки.

Базовая установка загружает FFmpeg Shared в `tools/ffmpeg/` и проверяет SHA-256 архива. Если подходящая локальная копия уже есть, установка её сохраняет. Для первоначального создания `.venv` setup проверяет `python` и `py`; если оба способа не сработали, он предлагает указать путь к установленному Python или выбрать установку через WinGet. При обработке видео локальная копия используется раньше системной. Сценарии MP4, MKV, длинных файлов, повторного запуска и `_dr`-обработки проверены на реальных входах до изменения установщика; новую установку на чистой машине нужно проверять отдельно. Конкретные тестовые файлы и результаты прогонов не являются частью контракта системы.

## Формат результатов

Для каждого исходного файла создаётся отдельная папка в `output/transcripts/`, повторяющая относительный путь внутри `input/`.

Основные файлы:

- `raw.json` — исходный экспорт GigaSTT;
- `transcript.json` — нормализованный транскрипт;
- `transcript.txt` — читаемая текстовая версия;
- `diarization.json` — интервалы голосов Community-1, если использовалось разделение говорящих;
- `error.txt` — описание ошибки, если обработка не завершилась успешно.

`raw.json` служит неизменяемой исходной точкой для производных представлений. Это позволяет менять правила форматирования и работы с голосами без повторного распознавания речи.

Если полный комплект результатов уже существует и его JSON читается корректно, повторный запуск пропускает файл. Если существующий результат повреждён, он не перезаписывается молча: обработка блокируется для ручной проверки.

## Нормализация транскрипта

`transcript.json` сохраняет слова и исходные таймкоды GigaSTT и группирует их в более крупные сегменты.

При разбиении учитываются:

- паузы между словами;
- конечные знаки препинания;
- максимальная длина сегмента;
- смена метки говорящего, если она уже присутствует.

Если оформленный текст с пунктуацией нельзя однозначно сопоставить с исходным массивом слов, скрипт предпочитает сохранить исходные слова вместо потенциально неверного сопоставления.

## YouTube

Для загрузки используется `yt-dlp`.

`youtube.cmd` и `youtube_dr.cmd` принимают ссылку на отдельное видео или плейлист, загружают аудиодорожки в `input/` и передают в следующие этапы только файлы, относящиеся к этой ссылке.

ID YouTube сохраняется в имени файла. Это позволяет повторно сопоставлять скачанное аудио с уже существующими транскриптами.

Существующее аудио не перезаписывается, а готовые транскрипты отдельно пропускаются основной обработкой. Локальный Node.js используется `yt-dlp` как JavaScript runtime, когда это требуется сайтом; локальное распознавание речи от Node.js не зависит.

## Разделение и идентификация говорящих

Для необязательного разделения говорящих используется локальная pyannote Community-1. Модель запускается после распознавания речи и работает с существующим `transcript.json`, поэтому повторный STT не требуется.

Текущий установщик ставит CUDA-сборку PyTorch и в первую очередь ориентирован на NVIDIA GPU. Если CUDA недоступна, `scripts/diarize.py` использует CPU.

Временный WAV 16 кГц создаётся только на время передачи конкретной записи в Community-1 и удаляется после завершения или ошибки. Метки `SPEAKER_00`, `SPEAKER_01` и т. п. обозначают различимые голоса внутри конкретной записи, а не личности людей.

Установка, повторная обработка, формат `speaker_names` и правила сопоставления меток с именами описаны в [SPEAKER_IDENTIFICATION.md](SPEAKER_IDENTIFICATION.md).

## Поведение при ошибках и повторном запуске

Обработка файлов выполняется независимо: ошибка одного входа не должна уничтожать уже готовые результаты других файлов.

При ошибке транскрибации создаётся `error.txt`. После успешного повторного запуска прежний файл ошибки удаляется.

Разделение говорящих также обрабатывает выбранные записи по отдельности и сообщает итоговый список неудачных файлов. Сохранённый `diarization.json` может повторно использоваться для пересборки транскрипта без нового запуска модели.

`--rerun-model` намеренно блокируется при наличии `speaker_names`, потому что после нового прохода модели номера голосов могут измениться.

## Локальность, сеть и внешняя обработка

После первоначальной установки GigaSTT и моделей базовая транскрибация локальных файлов не требует сети.

Интернет требуется для первоначального получения GigaSTT и моделей, загрузки локальных FFmpeg Shared и Node.js, установки Python-зависимостей, загрузки YouTube и первого получения Community-1 через Hugging Face.

Аудио не отправляется в облачный сервис распознавания. LLM или AI-агент также не являются runtime-зависимостью проекта.

Агент может быть дополнительным потребителем `transcript.txt` и `transcript.json` и создавать meeting notes, краткие выжимки, списки решений и задач или другие производные материалы. Такие результаты должны оставаться отделены от дословного транскрипта.

## Принятые технические решения

- **GigaSTT Windows CLI вместо постоянно работающего сервера.** Для небольшой пользовательской утилиты это проще в установке и эксплуатации.
- **CPU как основной путь GigaSTT.** CUDA не является требованием для обычной транскрибации.
- **Python для orchestration и преобразования результатов.** Пользователь при этом работает через простые `.cmd`-точки входа.
- **FFmpeg только там, где требуется работа с контейнером или моделью.** Исходные медиафайлы не изменяются.
- **`yt-dlp` для получения YouTube-аудио.** Загрузка отделена от локального распознавания речи.
- **Community-1 как отдельный этап разделения говорящих.** Он не меняет исходный `raw.json` и может запускаться уже после получения транскрипта.
- **Локальные модели и результаты не входят в Git.** Репозиторий содержит только код, документацию и зависимости установки.

## Ограничения

- основной целевой сценарий — Windows;
- распознавание ориентировано на русскую речь;
- качество пунктуации и границ фраз зависит от моделей GigaSTT;
- прерванное распознавание отдельного большого файла начинается заново;
- разделение говорящих не гарантирует правильное количество реальных участников и не определяет их личности;
- YouTube зависит от поведения внешнего сервиса и совместимости текущего `yt-dlp`.
