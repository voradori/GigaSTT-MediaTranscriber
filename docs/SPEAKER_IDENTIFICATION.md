# Разделение и идентификация говорящих

Разделение говорящих является необязательным этапом поверх обычной транскрибации GigaSTT. Для него используется локальная модель [pyannote Speaker Diarization Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1).

Community-1 не распознаёт речь повторно. Она определяет временные интервалы разных голосов, после чего скрипт сопоставляет их с уже существующими словами и таймкодами из `transcript.json`.

`raw.json` при этом не изменяется. Результат модели сохраняется в `diarization.json`, а метки голосов добавляются в основные `transcript.json` и `transcript.txt`.

Метки вида `SPEAKER_00`, `SPEAKER_01` обозначают различимые голоса только внутри конкретной записи. Это не имена людей, и одинаковый индекс в разных записях не означает одного и того же человека.

## Требования и установка

Сначала должен быть выполнен обычный `setup.cmd`.

Для Community-1 нужен аккаунт Hugging Face с принятыми условиями доступа к модели. Затем из корня проекта запусти:

```text
setup-diarization.cmd
```

Установщик:

- использует общую `.venv` проекта;
- устанавливает pyannote и необходимый стек PyTorch;
- при необходимости устанавливает FFmpeg Shared;
- предлагает войти в Hugging Face штатным CLI-механизмом;
- загружает Community-1 в локальную папку `models/`;
- проверяет, что модель может быть загружена локально.

Текущий установщик ставит CUDA-сборку PyTorch и в первую очередь рассчитан на NVIDIA GPU. Если CUDA недоступна, рабочий скрипт переключается на CPU. Такой режим не требует NVIDIA-видеокарты, но обработка может быть заметно медленнее.

Токены Hugging Face не должны сохраняться в файлах проекта или попадать в Git.

## Команды

Для новых локальных файлов с разделением говорящих:

```text
transcribe_dr.cmd
```

Для YouTube-видео или плейлиста:

```text
youtube_dr.cmd
```

Команды без суффикса `_dr` выполняют только транскрибацию.

Для уже существующих транскриптов используется:

```text
diarize.cmd
```

Без параметров команда обрабатывает подходящие транскрипты в `output/transcripts/`. Можно ограничить обработку конкретным файлом или папкой внутри `input/`, а для YouTube также использовать:

```text
diarize.cmd --id VIDEO_ID
```

Если транскрипты уже существуют, но исходное YouTube-аудио было удалено, `download-audio.cmd` скачивает только звуковую дорожку и не запускает GigaSTT повторно.

## Результаты

После успешной обработки в папке записи находятся:

- `raw.json` — исходный результат GigaSTT, не изменяется;
- `transcript.json` — основной структурированный транскрипт с метками голосов;
- `transcript.txt` — читаемая версия с метками вида `[SPEAKER_00]`;
- `diarization.json` — исходные интервалы голосов Community-1.

Новые результаты не создают отдельные `transcript.speakers.json` и `transcript.speakers.txt`. Старые файлы такого формата могут быть удалены автоматически только при точном совпадении с новым результатом; отличающиеся версии сохраняются для ручной проверки.

Перед обработкой скрипт сопоставляет исходное аудио с транскриптом и проверяет длительность. Если подходящий файл не найден однозначно или длительность отличается более чем на одну секунду, эта запись завершается с ошибкой, не мешая обработке остальных.

Для временной подачи аудио в модель создаётся WAV 16 кГц. Он удаляется после успешного завершения или ошибки.

## Повторный запуск и переобработка

Повторный запуск безопасен: уже готовые корректные результаты пропускаются.

```text
diarize.cmd --force
```

`--force` заново строит `transcript.json` и `transcript.txt` из уже сохранённого `diarization.json`, не запуская модель повторно.

```text
diarize.cmd --rerun-model
```

`--rerun-model` повторно запускает Community-1 и заменяет разметку голосов.

Если в транскрипте уже есть `speaker_names`, повторный запуск модели блокируется до ручной проверки. После нового прохода номера `SPEAKER_XX` могут измениться, поэтому старое соответствие имён может стать неверным.

## Когда можно назначить голосу имя

Автоматическое разделение голосов само по себе не определяет личность человека.

Имя можно назначить, если в записи человек однозначно представился и контекст позволяет связать представление с конкретной меткой голоса.

Другой допустимый вариант: пользователь сообщает участников и даёт характерные дословные фразы. Агент может найти эти фразы в `transcript.json`, сверить таймкоды и метки и проверить несколько реплик одного человека.

Недостаточными основаниями являются:

- простое упоминание чужого имени;
- обращение к собеседнику;
- субъективная догадка по голосу;
- одно сомнительное совпадение фразы;
- одинаковый номер `SPEAKER_XX` в другой записи.

Если данных недостаточно, метку следует оставить без имени.

## Формат `speaker_names`

Имена хранятся только в словаре верхнего уровня `speaker_names` внутри `transcript.json`, например:

```json
{
  "speaker_names": {
    "SPEAKER_00": "Анна",
    "SPEAKER_01": "Борис"
  }
}
```

Ключи должны соответствовать реально встречающимся в этом транскрипте меткам.

Не заменяй сами значения `speaker` именами и не меняй ради идентификации слова или таймкоды. Это сохраняет связь с `diarization.json` и позволяет позднее исправить ошибочное имя без повторной обработки модели.

После изменения `speaker_names` пересобери текстовую версию:

```text
.venv\Scripts\python.exe scripts/render_transcript.py "output/transcripts/.../transcript.json"
```

В `transcript.txt` подписанная метка будет выглядеть как `[SPEAKER_00 — Анна]`. Неподписанные голоса сохраняют обычный индекс.

Если личность позже исправлена, достаточно изменить значение в `speaker_names` и заново построить `transcript.txt`.

## Ограничения

Community-1 различает голоса, но может разделить одного реального человека на несколько меток или ошибиться на коротких репликах, шуме и пересечении речи.

Количество найденных голосов не следует автоматически считать количеством реальных участников.

Смысловая выжимка, список решений или meeting notes являются отдельными производными материалами. Не выдавай их за дословный транскрипт и не приписывай слова конкретному человеку без достаточных оснований.
